## Phase 13（FR-24 机密字段加密，2026-08-16）
- 背景：原 `pin`(家长审批码 4–6 位) 与 `sync.pass`(WebDAV 密码) 均以明文存于 localStorage（`savePin` 直写 `c.pin=nw`、`saveSyncConfig` 直写 `s.pass=...`）。
- 两类机密语义不同、分别处理：
  - `pin` 仅需"输入比对"→ 单向哈希 `hashPin`(PBKDF2-SHA256, 10万迭代 + 16B salt)，落库 `{v:1,alg:"pbkdf2-sha256",salt,hash}`；`verifyPin` 重算并 `ctEq` 定长比较，零明文残留。
  - `sync.pass` 须向服务器以明文出示 Basic Auth、无法单向哈希 → 对称加密 `encryptSecret`(AES-GCM, 12B IV + 32B 密钥)；密钥来自每安装随机 KMS 键 `sunshine_station_kms`（独立于主存储键，使导出主 JSON 不含密钥）。落库 `{v:1,alg:"aes-gcm",iv,ct}`；`decryptSecret` 用时还原。
- 透明迁移 `migrateSecrets()`：`load()` 后顶层调用，对仍是 `^\d{4,6}$` 明文的 `pin` 原地哈希、对非空明文 `sync.pass` 原地加密；已是对象则跳过；`HAS_CRYPTO` 为假则直接返回（保留旧明文、由兼容路径兜底）。旧数据无需脚本平滑升级。
- 兼容与降级：所有加密边界(`verifyPin`/`decryptSecret`/`hasPin`)识别旧版明文串直接比对/原样返回；`HAS_CRYPTO=false` 时 `hashPin`/`encryptSecret` 退化 `{v:0,alg:"none"}` 不崩，功能可用（仅失静态加密，边界已在文档/UI 明示）。改 `ensureIds` 对 pin/pass 仅做空值兜底（不再强转 string），`importFile` 同理；`savePin`/`submitPin`/`saveSyncConfig`/`renderSyncPanel`/`scheduleAutoPush`/`doSyncPush`/`doSyncPull` 均改 async + 加密边界。
- 回归脚本新增 T40(PIN 哈希+校验+旧明文兼容)、T41(哈希可校验 crypto 路径)、T42(sync.pass AES-GCM 加密+还原+round-trip+旧明文兼容+载荷仍剔密)、T43(KMS 密钥稳定)、T44(ensureIds 保留对象格式)、T45(记住密码下 doSyncPush 用密文还原认证)。原有 T6/T7/T8/T9 的 `submitPin`/`savePin` 调用改为 `await`、T8 断言改为校验哈希对象（不再期望明文）。**全量 191/191 通过（T1~T45）**。
